Live demo · Distributed Compute Cluster

One node vs. four.

Both terminals run the same pipeline as the real cluster: split the input into chunks, bubble-sort each chunk on a worker node, then merge sorted files on the master as they come back. Here each "node" is a Web Worker running on your device, so the timings are real.

Press run to start both terminals at once.
master@127.0.0.1 — single node0.00s
$
master@127.0.0.1 — 4-node cluster0.00s
$

Split

The master reads the input and cuts it into fixed-size chunks, one job per chunk, just like cluster.submit(chunk_file) with dispy.

Sort

Each free node takes the next job and bubble-sorts it. Bubble sort is O(n²), so chunk size matters a lot. Try 5,000 to see why.

Merge & verify

The master merges sorted chunks two at a time as they arrive, then checks the result is in order and identical to a reference sort, the same as sort -n | diff.
